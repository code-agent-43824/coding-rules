# coding-rules

Канонический свод правил для кодинг-агентов — [`AGENTS.md`](AGENTS.md). Копируется
в остальные проекты как есть; проектное дописывается через «Приложение» в конце файла.

[`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md) — журнал решений: что и когда решено, что
в репозиториях расходится со сводом.

## Как Claude Code подхватывает правила

Ключевой факт: **Claude Code читает `CLAUDE.md`, а `AGENTS.md` сам по себе не читает.**
Правила подтягиваются строкой импорта `@AGENTS.md` в `CLAUDE.md` — она разворачивает
файл в контекст на старте сессии.

Импортируются только файлы **с диска**. Ссылка на репозиторий или на файл по URL
не работает: по сети правила не загружаются.

Обычная markdown-ссылка `[AGENTS.md](AGENTS.md)` — тоже не импорт, а просто текст,
который агент может и не открыть. Нужен именно `@AGENTS.md` вне обратных кавычек.

## В существующий репозиторий

```bash
cp ~/src/coding-rules/AGENTS.md .
printf '@AGENTS.md\n' > CLAUDE.md     # либо первой строкой в существующий CLAUDE.md
```

Если проектный `CLAUDE.md` не нужен вовсе, хватит симлинка (на Windows требует прав
администратора или режима разработчика):

```bash
ln -s AGENTS.md CLAUDE.md
```

Проверка: в сессии `/context` → раздел **Memory files**.

## В новый репозиторий, чтобы `/init` увидел правила первым проходом

Обычный `/init` читает правила Cursor и Copilot, но **не `AGENTS.md`**. Поэтому свод
кладётся до запуска:

```bash
git init myproject && cd myproject
cp ~/src/coding-rules/AGENTS.md .
printf '@AGENTS.md\n' > CLAUDE.md
git add -A && git commit -m "chore: add agent rules"
```

Дальше `/init` видит готовый `CLAUDE.md` и **предлагает дополнения, а не перезаписывает
его** — карта кода и команды допишутся ниже импорта, правила останутся одной строкой.

Второй вариант — заставить сам `/init` прочитать `AGENTS.md`:

```bash
CLAUDE_CODE_NEW_INIT=1 claude
```

В этом режиме `/init` читает `AGENTS.md`, `.devin/rules/`, `.windsurf/rules/`
и `.clinerules`, задаёт уточняющие вопросы и показывает результат до записи файлов.

## На всю машину сразу

Пользовательский `~/.claude/CLAUDE.md` применяется ко **всем** проектам и грузится
раньше проектного — то есть новый репозиторий подхватит правила без единого действия
в нём:

```bash
git clone https://github.com/code-agent-43824/coding-rules ~/src/coding-rules
printf '@~/src/coding-rules/AGENTS.md\n' >> ~/.claude/CLAUDE.md
```

`git pull` в клоне обновляет правила во всех проектах разом. Импорты в пользовательских
файлах памяти не требуют подтверждения — в отличие от импорта за пределы рабочего
каталога из проектного `CLAUDE.md`, где Claude Code один раз спросит разрешение.

**Это покрывает только вашу машину.** Claude Code в вебе и в облачных сессиях, другие
агенты (Codex, Copilot, Gemini) и любой сторонний участник видят только то, что лежит
в самом репозитории. Поэтому `AGENTS.md` всё равно коммитится в каждый проект.

## Чего делать не стоит

- **`/import`** копирует содержимое `AGENTS.md` внутрь `CLAUDE.md` разово. Это ровно
  то дублирование, которое запрещает §0: две копии разойдутся.
- **Пересказывать правила** в `CLAUDE.md`, `.github/copilot-instructions.md`
  или `GEMINI.md`. Там либо импорт, либо карта кода — то, чего нет в своде.
