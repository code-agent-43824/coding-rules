# coding-rules

Канонический свод правил для кодинг-агентов — [`AGENTS.md`](AGENTS.md). Копируется
в остальные проекты как есть; проектное дописывается через «Приложение» в конце файла.

[`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md) — журнал решений: что и когда решено, что
в репозиториях расходится со сводом.

## Как правила попадают к агенту

Claude Code читает **`CLAUDE.md`** в корне репозитория. Файл `AGENTS.md` сам по себе
он не открывает. Поэтому в каждом проекте лежат два файла:

| Файл | Содержимое |
| --- | --- |
| `AGENTS.md` | сами правила — копия из этого репозитория |
| `CLAUDE.md` | строка `@AGENTS.md`, которая подставляет их в контекст |

`@AGENTS.md` — не ссылка для чтения глазами, а импорт: он разворачивает файл в контекст
при старте сессии. Обычная markdown-ссылка `[AGENTS.md](AGENTS.md)` этого не делает.

**В облачных сессиях работает только то, что закоммичено в репозиторий.** Сессия
стартует с чистого клона на новой виртуальной машине: пользовательский
`~/.claude/CLAUDE.md` туда не попадает, машинные настройки тоже. Так что путь один —
два файла в репозитории.

## Установка и обновление

Из корня репозитория:

```bash
curl -fsSL https://raw.githubusercontent.com/code-agent-43824/coding-rules/main/install.sh | bash
```

Скрипт скачивает свежий `AGENTS.md` и добавляет импорт в `CLAUDE.md` — создаёт файл,
если его нет, или ставит строку первой, если файл уже есть. Запускать можно повторно:
для обновления правил это та же команда.

Дальше остаётся закоммитить:

```bash
git add AGENTS.md CLAUDE.md && git commit -m "chore: update agent rules" && git push
```

То же самое можно просто попросить словами прямо в сессии: «поставь правила
из `code-agent-43824/coding-rules`».

## Новый репозиторий

Правила нужно положить **до** запуска `/init`, иначе он создаст свой `CLAUDE.md` без них:

```bash
git init && curl -fsSL https://raw.githubusercontent.com/code-agent-43824/coding-rules/main/install.sh | bash
git add -A && git commit -m "chore: add agent rules"
```

После этого `/init` видит готовый `CLAUDE.md`, **не перезаписывает** его, а дописывает
ниже импорта команды сборки и карту кода.

Обычный `/init` читает правила Cursor и Copilot, но `AGENTS.md` не читает. Прочитать
его самостоятельно он может в расширенном режиме — `CLAUDE_CODE_NEW_INIT=1`, — но
в облачной сессии переменную задавать негде, кроме настроек окружения, так что проще
класть файлы заранее.

## Чтобы правила были во всех облачных сессиях сразу

В настройках облачного окружения на claude.ai есть **Setup script** — bash, который
выполняется от root до запуска Claude Code. Он может положить правила на уровень
пользователя, и тогда они действуют в любой сессии этого окружения, даже в репозитории,
куда их ещё не клали:

```bash
#!/bin/bash
mkdir -p /root/.claude
curl -fsSL https://raw.githubusercontent.com/code-agent-43824/coding-rules/main/AGENTS.md \
  -o /root/.claude/CLAUDE.md || true
```

`|| true` обязателен: если скрипт завершится с ненулевым кодом, сессия не стартует.

Это **страховка, а не замена** файлам в репозитории: setup-скрипт виден только вам
и только в этом окружении, его не видно в истории проекта, и другие агенты (Codex,
Copilot, Gemini) читают исключительно то, что лежит в репозитории.

## Проверить, что сработало

В сессии — `/context`, раздел **Memory files**: там должен быть `CLAUDE.md`.

## Чего делать не стоит

- **Давать агенту ссылку на этот репозиторий вместо файлов.** Правила загружаются
  только с диска; по URL Claude Code их не подтянет.
- **`/import`** копирует содержимое `AGENTS.md` внутрь `CLAUDE.md` разово — то самое
  дублирование, которое запрещает §0: две копии разойдутся.
- **Пересказывать правила** в `CLAUDE.md`, `.github/copilot-instructions.md`
  или `GEMINI.md`. Там либо импорт, либо карта кода — то, чего нет в своде.
